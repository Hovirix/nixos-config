# Repository Instructions

## Source Of Truth
- The root `flake.nix` defines one NixOS config, `nixosConfigurations.laptop`; there are no separate `laptop/`, `server/`, or `docs/` directories in the current tree.
- `flake.nix` manually wires every active module. Adding a module file under `modules/` does nothing until it is added to the `modules = [ ... ]` list for `laptop`.
- `specialArgs` provides `inputs`, `username = "nixos"`, and `hostname = "laptop"`; modules commonly depend on these instead of hardcoding user/host values.

## Commands
- Format Nix files with `nix fmt` (`formatter.x86_64-linux` is `nixfmt-tree`).
- Run the repo-level verification with `nix flake check`; it currently passes and emits the warning that `system` was renamed to `stdenv.hostPlatform.system`.
- Build the laptop system without switching with `nixos-rebuild build --flake .#laptop`.
- Apply the system with `sudo nixos-rebuild switch --flake .#laptop` only when explicitly asked.

## Secrets
- Age-encrypted secrets live in `secrets/*.age`; do not replace them with plaintext.
- New agenix secrets need both a declaration in `secrets/secrets.nix` and an `age.secrets.<name>` entry in the module that consumes them.
- Existing encrypted secret consumers are `modules/services/wireguard.nix` and `modules/services/restic.nix`; WireGuard also sets `age.identityPaths = [ "/home/${username}/.ssh/id_ed25519" ]`.

## Commits
- Use Conventional Commits: `type(scope): short imperative summary`.
- Prefer repo scopes from the tree or subsystem: `core`, `desktop`, `dev`, `hardware`, `services`, `secrets`, `nix`, or `docs`.
- Keep unrelated system, secret, and documentation changes in separate commits; use `chore(secrets): ...` for encrypted secret rotations.

## Layout Notes
- `system/disko.nix` targets a specific NVMe disk by ID and configures LUKS/ext4; treat storage edits as machine-specific and high risk.
- `system/hardware-configuration.nix` is generated by `nixos-generate-config`; prefer changing separate modules unless regenerating hardware config is the task.
- Secure boot is handled by `modules/core/boot.nix` with lanzaboote and `/var/lib/sbctl`; bootloader changes can affect key enrollment and reboot behavior.
